# Verificacion y Validacion

## 1. Diferencia aplicada al proyecto

**Verificacion** responde si construimos correctamente el producto especificado:
que las reglas RN/RF esten implementadas en el modulo correcto, que las guardas
se ejecuten antes de persistir, que las salidas de CLI no filtren errores
internos, que los datos demo sean reproducibles y que la suite automatizada
pase.

**Validacion** responde si construimos lo que realmente necesita el uso esperado:
que una persona pueda iniciar sesion, pedir, aprobar, entregar, devolver,
cancelar y consultar prestamos; que los bordes del calendario/cupo se comporten
como espera el laboratorio; que los datos demo permitan reproducir el sistema; y
que pruebas cruzadas hechas por otro integrante encuentren o descarten defectos
relevantes.

No se aceptan definiciones unicamente teoricas: cada actividad registrada abajo
fue ejecutada o revisada y tiene evidencia enlazada en el repositorio o en los
PRs reales del proyecto.
